## 2026-06-11（第十八輪）—— 戰鬥程序化動畫層（走/攻/傷/狀態，英雄＋怪物皆動）
- **分支／PR**：`claude/battle-animation`（完成後自助合併進 `main`）
- **核心需求（使用者原話）**：「所有角色UI應該好好設計，然後我希望動起來（走路時、攻擊時、受傷害時、被效果時…）更豐富的設計，怪物 角色都是」。
- **設計取捨**：113 隻精靈各畫多幀動畫不可行；改走**程序化變換動畫**——利用上一輪做的**精靈快取（drawImage）**，每幀對快取圖套 `ctx` 變換（繞腳底 translate→rotate→scale），成本極低、英雄/怪物**共用同一套**、零新美術。
- **解法（`render.js`）**：
  - 新增 `bodyAnim(u, facing, moving, flying, idx, clk)` → 回傳 `{rot, sx, sy, oy}`，由單位狀態驅動：
    - **待機呼吸**：全體輕微 squash/stretch（sin，idx 去同步）→ 畫面隨時有生命感（冰凍時凝固）。
    - **走路**：跳步 hop＋身體左右搖擺 rot＋觸地壓縮（英雄＝march 期間；怪物＝`e.x - e.moveTX > 1.5` 接近中）。
    - **飛行**：上下漂浮＋微傾（取代走路）。
    - **攻擊**：依 `lunge`（峰值衰減）前傾 lean＋scale pop＋上抬（面向 facing：英雄右、怪物左）。
    - **受傷**：依 `hitFlash` 壓扁＋既有白閃＋shake jitter。
    - **狀態**：暈/麻 wobble、燃燒抖動、冰凍凝固；疊加既有 `drawFx` 覆蓋特效。
    - 防呆：scale 夾在 0.7–1.4。
  - 英雄與敵人繪製皆以 `ctx.save(); translate(腳底); rotate; scale; translate(-腳底); drawSprite(...); restore()` 包住；血條/狀態特效在 restore 後繪製（保持直立）。移除舊的 1px `bob`（由 hop 取代）。版本 `?v=109→110`。
  - 驗證：`node --check` 全綠；戰鬥煙霧＋三轉隊 60s **12 通過/0 失敗**（stub ctx 變換/快取回退皆不 throw）。
- **狀態**：✅ 完成並合併進 `main`。
- **接下來 / 期望**：實機看動畫手感（呼吸幅度/攻擊前傾/旋轉鋸齒是否需微調）；可選後續：攻擊「預備動作」需 game.js 加 windup 計時；死亡動畫需保留屍體短暫；戰鬥內角色 UI（造型化血條/名牌/狀態圖示列）；招募/數值平衡。
